# py++ 快速精通

> 一门源文件后缀为 **`.cpy`** 的编程语言：  
> **像 Python 一样简洁的语法 + 接近 C++ 的速度 + 小错误自动兼容**。
>
> 这份指南按「从零到精通」编排。前 3 章让你跑起来，第 4～6 章是理解 py++ 的关键，  
> 第 7～9 章是生态（装库 / C 库），**第 10 章「已知边界」请务必读完** ——  
> 它列出了目前做不到的事，能帮你少踩坑。

---

## 0. 一分钟认识 py++

三个承诺，以及一个诚实的边界：

| 承诺         | 说明                                            |
| ---------- | --------------------------------------------- |
| 语法像 Python | 缩进分块、无分号、`print("hi")`、`def`、`class`、`import` |
| 速度接近 C++   | **原生模式**实测比等效 C++ 慢约 12%（见第 5 章）              |
| 小错误自动兼容    | 拼写错、缺冒号、未定义变量、全角标点、换行拆散……都能跑                  |

**诚实的边界**：「接近 C++」只对**原生模式**成立。没有 gcc 时会降级到内置  
VM 引擎兜底，功能一致但**慢 3000～7000 倍**。向别人介绍 py++ 时，别把两者混为一谈。

## 1. 安装与命令（10 分钟）

### 安装

- **普通用户**：双击 `pypp-1.1.0-setup.exe`，按向导点下一步。  
  安装程序**自带 Python 运行时**，你的机器不需要预先装 Python。
- **开发者**：在源码目录执行 `python install_gui.py`（图形向导）  
  或 `python install.py`（命令行）。

安装时可选「是否安装便携 C 编译器」——**装不装是速度分水岭**：

- 勾选 → 原生高速模式（速度接近 C++），工具链约 557MB
- 不勾 → 内置 VM 模式（较慢但完全能用），核心代码不到 1MB

### 四条命令

| 命令                   | 作用               |
| -------------------- | ---------------- |
| `pypp <文件.cpy>`      | 编译并运行            |
| `pypp <文件.cpy> --vm` | 强制用内置 VM（不用 gcc） |
| `pypp --check`       | 检查本机环境           |
| `pypp -v`            | 查看版本             |

装库用三个平级命令（详见第 7 章）：

| 命令                  | 管什么            |
| ------------------- | -------------- |
| `pyget install <包>` | Python 库（PyPI） |
| `cget install <库>`  | C 库            |
| `cpget install <库>` | C++ 库          |

### 双击就能跑

Windows 上注册过 `.cpy` 文件关联后，**直接双击任意 `.cpy` 文件**即可运行，  
不必先打包成 exe。控制台里 `pypp --check` 验证环境：

```
py++ 1.1.0 环境检测
  Python: 3.13.15
  ✓ C 工具链: ...\tools\mingw64\mingw64\bin\gcc.exe
  执行引擎: 原生高速模式
  ✓ 可嵌入 CPython: ...\Python313 (3.13)
  import 支持: 原生模式直接嵌入 CPython
  第三方包目录: C:\Users\你\.pypp\packages
```

## 2. 第一个程序

新建 `hello.cpy`：

```python
name = "py++"
print("hello, " + name)

total = 0
for i in range(1, 101):
    total += i
print("1 加到 100 =", total)
```

运行 `pypp hello.cpy`：

```
[py++] 引擎: 原生高速模式 (gcc.exe)  |  文件: hello.cpy
hello, py++
1 加到 100 = 5050
[py++] 完成 编译 178ms | 运行 127ms  (原生模式)
```

三行输出各有含义：第一行是**用了哪个引擎**，中间是程序输出，最后是耗时。  
**判断速度时先看第一行**——只有"原生高速模式"才配谈性能。

## 3. 语言基础速通

py++ 目前覆盖日常开发的大部分语法，按 Python 的直觉写即可。

### 变量与类型

不用声明类型，编译器自己推导（整数映射 C 的 `long long`，字符串走专用结构体）：

```python
n = 42              # 整数
pi = 3.14           # 浮点
s = "hello"         # 字符串
ok = True           # 布尔
```

### 运算与比较

```python
print(7 // 2, 7 % 2, 2 ** 10)      # 3 1 1024
print(1 < 2 and 3 > 2)             # True
print(not False)                   # True
```

### 控制流

```python
if x > 5:
    print("大")
elif x > 0:
    print("小")
else:
    print("负")

for i in range(3):        # range 编译成原生 for 循环，不带运行时开销
    print(i)

while n > 0:
    n = n - 1
```

### 函数

```python
def add(a, b):
    return a + b

print(add(1, 2))          # 3
```

### 输入输出

```python
name = input("你叫什么? ")
print("你好,", name)
```

`print` 支持多参数自动拼接，也可以不写括号。

### 字符串

```python
s = "py++"
print(s + " 语言")        # 拼接
print(len(s))             # 长度
```

## 4. 招牌能力：小错误自动兼容

这是 py++ 的招牌。看一个**故意写错**的程序（`examples/tolerant.cpy`）：

```python
pritn("开始运行")      # pritn 拼错了

x = 10
y = 20
if x > 5               # 少了冒号
    print("x 大于 5")

print("结果 =", x + y)
print(z)               # z 从未定义
```

运行结果：

```
[py++] 引擎: 原生高速模式 (gcc.exe)  |  文件: tolerant.cpy
开始运行
x 大于 5
结果 = 30
0
[py++] 温馨提示] 检测到你的代码有 3 处小错误，并无大碍，py++ 已兼容运行。
  [已自动修复] 第 6 行 'pritn' 疑似拼写错误，已自动更正为 'print'
  [已自动修复] 第 11 行 此处缺少 :，已自动补全，程序照常运行
  [已自动修复]  未定义的变量 'z'，已按 0 处理
[py++] 完成 编译 178ms | 运行 127ms  (原生模式)
```

### 能修哪些

| 类型    | 例子                                         |
| ----- | ------------------------------------------ |
| 拼写错误  | `pritn` → `print`（内置名 + 关键字，编辑距离算法）        |
| 全角标点  | `prinf（l）` 里的全角括号归一化成半角                    |
| 缺标点   | `if x > 5` 补冒号                             |
| 未定义变量 | 编译期补 `long long z = 0;`，不报错                |
| 换行拆散  | `prin` / `f` / `("hi")` 三行拼回 `print("hi")` |

### 为什么快没变慢

**修复全部发生在编译期**。生成的 C 代码是干净的——没有运行时类型检查、  
没有防护性分支。这正是 py++ 能贴着 C++ 性能跑的原因。

### 它怎么防止"越修越错"

三道防线，缺一不可：

1. **短词不猜** —— 长度 < 3 的词（`nn`、`nd`）一律不动，避免 `nn`→`in`
2. **首字母必须相同** —— `rpint` 因此修不了（这是刻意的取舍）
3. **上下文豁免** —— 你自己定义的变量名、函数名、参数名、类名、  
   import 的绑定名**以及模块名的每一级**，绝不改动

第 3 条是防止误伤的关键：没有它，`Point` 会被改成 `print`（编辑距离 1），  
`from urllib.parse import quote` 里的 `parse` 会被改成 `pass`。

### 诚实的边界

**宁可不修，也不猜错。** 当信息已经损坏、多种"本意"都合理时  
（比如 `prinf(l)` / `f` / `(...)`），py++ 只报告"无法确定你的本意"，  
不会瞎改——猜错比不修更糟，那会让你以为代码是对的。

## 5. 速度的真相：两套引擎

### 两套引擎

|      | 原生模式                     | VM 模式             |
| ---- | ------------------------ | ----------------- |
| 怎么工作 | 生成 C 代码，`gcc -O2` 编译成机器码 | 内置树遍历解释器          |
| 速度   | 比 C++ 慢约 12%             | 慢 **3000～7000 倍** |
| 何时用到 | 有 gcc（默认）                | 没 gcc 时自动兜底       |

### 怎么判断刚才用了哪套

**只看输出里的标记行**，别靠猜：

```
[py++] 引擎: 原生高速模式 (gcc.exe)  |  文件: hello.cpy
...
[py++] 完成 编译 178ms | 运行 127ms  (原生模式)
```

⚠️ 一个隐蔽的坑：提示语里出现"原生模式"字样**不代表**真的用了原生模式  
（VM 下有些提示也会提到这个词）。只认「引擎:」这一行。

### 原生模式会静默降级

如果生成的 C 编译失败，py++ 会自动切到 VM 继续跑，并提示  
"原生编译未成功，已自动切换到 py++ 内置引擎"。

**这意味着：你看到的输出可能是对的，但速度是 VM 的。** 关心性能时务必核对标记行。

### 编译缓存

第二次跑同一个程序会复用上次的编译结果，从几百毫秒降到 10～50ms。  
缓存键基于**生成的 C 代码**（而非原始源码），所以任何修复行为的变化  
都会自动失效，比源码哈希更安全。

环境变量：`PYPP_NO_CACHE=1` 关闭，`PYPP_CACHE_DIR` 换目录。

### 实测数字

测试脚本 `bench/run_bench.py`（需 gcc），内容为 5000 万次整数累加 +  
2000 万次浮点加法 + 2000×2000 嵌套循环取模，gcc 14.2.0 `-O2`，5 次取中位数：

| 项目   | C++     | py++（原生） | 倍率         |
| ---- | ------- | -------- | ---------- |
| 综合用时 | 0.030 s | 0.033 s  | **1.123x** |

## 6. 数据结构与抽象

### 列表

按元素类型编译成专用结构，不带运行时装箱：

```python
nums = [1, 2, 3]
names = ["a", "b"]
print(nums[0], len(nums))     # 1 3
```

### 字典

哈希表 + **插入顺序表**——遍历顺序与 Python 字典完全一致：

```python
d = {"apple": 3, "banana": 2}
d["cherry"] = 1
for k in d:
    print(k, d[k])
# apple 3
# banana 2
# cherry 1
```

### 类

编译成 **C 结构体 + 一组函数**，没有 vtable、没有运行时开销：

```python
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

    def total(self):
        return self.x + self.y

p = Point(3, 4)
print(p.total())              # 7
```

字段类型从**调用点推断**，不用写声明。示例见 `examples/class.cpy`。

## 7. 装库：三条命令各管一摊

py++ 的包管理是**三个平级命令**，不用猜：

| 命令                  | 管什么            | 装到哪                     | 在 `.cpy` 里        |
| ------------------- | -------------- | ----------------------- | ----------------- |
| `pyget install <包>` | Python 库（PyPI） | `~/.pypp/packages`      | `import requests` |
| `cget install <库>`  | C 库            | `~/.pypp/packages/_c`   | `import z`        |
| `cpget install <库>` | C++ 库          | `~/.pypp/packages/_cpp` | `import stdc++`   |

三个命令都支持完整子命令：`install` / `uninstall` / `list` / `show` /  
`freeze` / `search` / `download` / `doctor`，C/C++ 另有 `cbind`（转译头文件）  
和 `clibs`（列本机可用的库）。老名字 `pget` 仍保留，会自动识别。

### 实际用一遍

```bash
pyget install requests          # Python 库，递归装依赖
cget  install zlib              # C 库，自动找 zlib.h 并转译
cpget install stdc++            # C++ 标准库
```

`cget install zlib` 的输出：

```
cget 识别为 C 库：zlib  (匹配到 zlib.h)
✓ 已生成 19 条 extern 声明 → ~/.pypp/packages/_c/z.cpyi
cget   其中 77 个函数无法表达（变参/函数指针等），已注明原因
✓ 完成：已安装 C 库 z
  在 .cpy 里用：import z
```

### `import` 一条语法通吃三种库

```python
import requests      # Python 库 —— 走真实 CPython
import z             # C 库    —— 编译期展开成 #link + extern
import stdc++        # C++ 库  —— 同上
```

对 C/C++ 库，`import` 做的是**编译期展开**（零运行时开销）：  
py++ 发现 `~/.pypp/packages/_c/z.cpyi` 存在，就把里面的 `#link z` 和  
`extern` 声明直接铺进你的源码。

### 换镜像源

```bash
pyget install -i https://pypi.tuna.tsinghua.edu.cn/simple numpy
```

## 8. Python 生态：import 进来的是真 CPython

py++ 不是"重新实现 Python 库"，而是**把真的 CPython 嵌进编译产物**：

- 原生模式：链接 `python3XX.lib`，生成 C-API 调用
- VM 模式：VM 本身跑在 Python 里，import 是原生能力

所以**二进制扩展也能用**（Pillow 已实测跑通）。两个引擎看到同一批包——  
`~/.pypp/packages` 会被加进 `sys.path`，不会出现"原生能跑、VM 找不到模块"。

```python
import io
import hashlib

f = io.open("data.bin", "rb")
h = hashlib.sha256()
h.update(f.read())
print(h.hexdigest())
f.close()
```

> ⚠️ py++ **不支持 `b"..."` bytes 字面量**（会按普通标识符解析并被容错层改坏）。  
> 需要"二进制数据"时用 `io.open(path, "rb")` 读文件——上面这段跑出来的  
> 结果与 Python 逐位一致。直接 `hashlib.sha256("str")` 会 TypeError  
> （Python 侧要求 bytes），请务必走文件。

诊断环境：`pyget doctor`（会报告目标 Python、能否嵌入、版本是否一致）。

## 9. C / C++ 库互操作

py++ 编译到 C，所以调 C 库是它的原生能力，不用写 FFI 胶水。

### 手写声明

```python
#link z
extern unsigned long crc32(unsigned long crc, ptr, unsigned int len)

print(crc32(0, "hello", 5))      # 907060870
```

两件事分工：`extern` 让**编译器**认识这个函数，`#link` 让**链接器**找到实现。

### 自动转译

```bash
cget install zlib                        # 按库名
cget cbind C:/mingw64/include/zlib.h --link z --out zlib.cpyi   # 指定头文件
```

转译时会跟随 `#include` 递归收集 typedef（否则 `uLong` 这类类型收不全）。  
无法表达的函数（变参、函数指针、位域）会跳过并逐条注明原因。

### ⚠️ C ABI 宽度必须保真

这是"调 C 库很简单"背后真正的难点：

- **`int` 是 32 位**。声明成 64 位，返回值高位是未定义的垃圾值
- **无符号返回值必须零扩展**，否则 `crc32("py++")` 会显示成负数  
  （正确值 3415681142）

用 `cget` 自动转译能避开大部分坑，手写声明时请对照头文件核对宽度。

## 10. 已知边界（务必读完）

py++ 还在成长。以下是**目前做不到或行为有异**的地方，提前知道能少踩坑。

### 从 Python 库拿到的对象（`pyobj`）

`import` 进来的 Python 对象，真值判断和比较是**指针语义**：

| 写法                      | 实际行为                | 正确做法                         |
| ----------------------- | ------------------- | ---------------------------- |
| `if os.path.isfile(p):` | **恒为真**（即使文件不存在）    | `if int(os.path.isfile(p)):` |
| `obj == True`           | **恒为 False**        | 先 `int(...)` 再比              |
| `a == "x"`（两个 py++ 字符串） | 原生模式编不过，**静默降级 VM** | 暂时别用字符串比较做分支                 |

**规律：`int(...)` 是唯一安全的转换**（走 `PyNumber_Long`，`True`→1、`False`→0）。  
凡是要判断"存在性/真假"的地方，都包一层 `int()`：

```python
import os
if int(os.path.isfile("data.txt")):
    print("文件在")
```

### 没有 try / except

py++ 目前没有异常机制。错误处理只能靠**预检**：

```python
import os
if int(os.path.isfile(path)):
    ...                     # 确定存在再操作
```

### 命令行参数不会传进编译产物

`pypp prog.cpy a b c` 里的 `a b c` **不会**出现在程序里  
（第二个非 flag 参数还会覆盖文件路径）。程序要输入只能走 `stdin`：

```bash
echo "hello" | pypp prog.cpy
```

### 本地模块导入受限

原生模式下 `import` **找不到同目录的 `.cpy` / `.py` 模块**：  
`pkg/main.cpy` 里 `import mod`，`mod.val` 会得到 `None`（VM 下则是 `0`）。  
根因是脚本所在目录没被加进 `sys.path`。跨文件复用目前请把代码写在同一个文件里，  
或装成 Python 包再用 `pyget`。

### 其他

| 项                 | 状态                                                           |
| ----------------- | ------------------------------------------------------------ |
| `from x import *` | 原生模式无法编译期展开名字 → 自动降级 VM（功能一致）                                |
| C/C++ 库           | **只在原生模式可用**（VM 没有 C 运行时，会明确提示而非静默返回 0）                      |
| C 库来源             | `cget` 做的是「转译声明 + 链接」，**不下载 C 库**——库要先装在本机                   |
| 容器传递              | 字典/列表是**引用语义**（对齐 Python）：`inner["x"]=1` 后 `outer["a"]` 会跟着变 |
| gcc 静默失败          | 用 bash 直接调 gcc 可能无声失败；调 gcc 请走 Python `subprocess`           |

## 12. FAQ

**Q：为什么我的程序跑得慢？**  
看输出第一行的「引擎:」。如果是 VM 模式，装一下 gcc 或重跑安装程序勾选编译器。

**Q：改了代码但结果没变？**


第二次运行会复用编译缓存。若怀疑缓存问题，设 `PYPP_NO_CACHE=1` 再跑。

**Q：装完 exe 还是提示找不到 Python？**
exe 版自带运行时。若用源码安装，请确认系统有可用的 Python 3
（跑图形向导的那份还需要带 tkinter）；`pypp --check` 可诊断。

**Q：`import` 进来的库怎么判断它是 Python 对象还是 py++ 原生值？**
对它的判断一律先 `int(...)` 就安全（见第 10 章）。

**Q：可以把我写的 .cpy 分享给别人吗？**
可以，文件是纯文本。对方有 py++ 就能跑；在 Windows 上双击也能直接运行。

**Q：性能数字可信吗？**
可复现：`python bench/run_bench.py`（需 gcc）。测试用 stdin 传参防止常量折叠。
