# py++ 源码包 · 安装说明

> ⚠️ **这是源码分发包，不是安装包。**
> 如果你只是想在电脑上跑 `.cpy` 程序，**请下载 `pypp-1.1.0-setup.exe`**（约 24MB），
> 双击安装即可，不需要装 Python，也不需要看这份文档。

---

## 这个包里是什么

| 目录/文件 | 内容 |
|---|---|
| `src/` | 编译器核心（词法、语法、代码生成、容错修复、VM 解释器） |
| `examples/` | 9 个示例程序，`.cpy` 后缀 |
| `install.py` / `install_gui.py` | 安装脚本（CLI / 图形界面） |
| `pget.py` + `pyget.bat` / `cget.bat` / `cpget.bat` | 包管理器（Python / C / C++ 三套） |
| `web/server.py` | 在线试运行服务（可选） |
| `快速精通.md` | 语言指南，建议先读 |
| `README.md` | 项目说明与版本更新 |

**包内不含**：Python 运行时、C 编译器（gcc）、编译好的 exe。
这些需要你自己准备——这就是源码包和安装包的区别。

## 快速开始

### 前提

需要 **Python 3.10+**（3.13 已验证）。

```bash
python --version
```

### 直接运行一个示例（最快验证）

```bash
cd pypp-1.1.0
python src/pypp.py examples/hello.cpy
```

看到 `hello world` 就说明能用了。

### 安装（生成 pypp 命令 + 文件关联）

```bash
python install.py
```

装完后：
- 命令行可用 `pypp hello.cpy`
- 双击 `.cpy` 文件可直接运行（由 `src/assoc.py` + `src/runner.py` 负责）

图形界面版：

```bash
python install_gui.py
```

## ⚠️ 关于「原生模式」和「内置 VM 模式」

py++ 有两条执行路径，**性能差几千倍**，这点务必搞清楚：

| 模式 | 条件 | 速度 |
|---|---|---|
| **原生高速模式** | 找到 C 编译器（gcc） | 接近 C++（实测慢 1.02~1.12 倍） |
| **内置 VM 模式** | 找不到 gcc 时的兜底 | **慢 3000 倍以上**，仅保证能跑 |

**源码包默认不带 gcc**，所以首次运行很可能是 VM 模式。想跑出真实速度，
需要准备 gcc 并让 py++ 找到它：

- Windows 推荐 [winlibs](https://winlibs.com/) 的 MinGW-w64（解压即用）
- 把 `gcc.exe` 所在目录放进 `PATH`，或解压到 py++ 能找到的位置

运行时会打印用的是哪个引擎：

```
[py++] 引擎: 原生高速模式 (gcc.exe)    ← 这才是应有的样子
[py++] 引擎: 内置 VM 模式              ← 没找到 gcc，性能不代表 py++
```

## 装第三方库

```bash
pyget install requests     # Python 包（来自 PyPI）
cget install z             # C 库
cpget install <C++库>      # C++ 库
```

装好后在 `.cpy` 里直接 `import`：

```python
import requests
import z
```

## 常见问题

**Q：双击 `.cpy` 没反应，或者窗口一闪就没了？**
用命令行跑一次看错误：
```bash
python src/pypp.py 你的文件.cpy
```
如果提示找不到模块，说明当前目录不对，`cd` 到脚本所在目录再跑。

**Q：程序跑出来的速度比预期慢很多？**
看引擎提示。如果是「内置 VM 模式」，说明没找到 gcc——见上面那节。

**Q：`extern` 调 C 函数崩溃？**
检查声明是否与头文件签名一致（参数个数、类型、顺序）。py++ 会尽量在校验阶段
拦截明显不匹配的声明，但无法覆盖所有情况。用 `pget cbind` 可以自动转译头文件：

```bash
python pget.py cbind zlib.h -l z
```
